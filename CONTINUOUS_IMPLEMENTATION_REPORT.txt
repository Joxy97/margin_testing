3-5. EXACT MINIMAL SAVED RESULT FORMATS
raw/<solver>/<problem>.npy: float64 matrix (100,9) by default, one best_energy
per seed/checkpoint. Seed IDs and9 checkpoint times occur once in manifest.json.
NaN denotes unavailable energy. No assignment is stored even for a reference hit.
aggregated/<solver>/<problem>.csv: exactly9 rows and4 columns:
checkpoint_seconds,gap_to_solution,hit_probability,TTS99
Solver/problem names occur in path context. Reference info occurs once/problem.
Small progress/state/completion files hold immutable identity, statuses and
checksums only. All writes are atomic; interrupted seeds restart in full.
With --no-keep-raw-results, raw energies and their per-row checksums are removed
only after durable aggregation/completion. Aggregate checksums/statuses remain.

6. ONE CONTINUOUS RUN, NOT NINE SEPARATE TESTS
One fresh solver/RNG state, one solve call, one20s observation window.
Nine boundaries read the most recent fully completed independently scored
incumbent. Late results are not back-credited. Checkpoint GPU-to-host transfer
is scalar-sized, not proportional to variable count. Natural early returns
are carried forward without restarting or changing protected algorithms.
Mutable18 wall schedules and parameters are an explicit separate tuning mode,
not a hidden algorithm change needed for storage. Original defaults are kept.
